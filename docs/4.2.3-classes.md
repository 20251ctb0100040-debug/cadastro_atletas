# 4.2.3 Modelagem de Classes

## 1. Dos Substantivos às Classes

A identificação das classes foi realizada a partir dos casos de uso e dos requisitos funcionais definidos na seção 4.2.2. Foram analisados os substantivos presentes nas funcionalidades do sistema, identificando quais representam informações que precisam ser armazenadas.

| Substantivo identificado | Análise | Resultado |
|---|---|---|
| Atleta | Representa uma pessoa que participa dos Jogos Estudantis e possui informações que precisam ser armazenadas. | Classe Atleta |
| Modalidade | Representa uma atividade esportiva que pode estar relacionada aos atletas. | Classe Modalidade |
| Cadastro | Representa uma ação realizada pelo sistema, não uma informação independente. | Operação |
| Consulta | Representa uma ação realizada pelo usuário. | Operação |
| Administrador | Representa um ator que utiliza o sistema. | Ator |
| Responsável pelos Jogos | Representa um ator que consulta as informações dos atletas. | Ator |

As classes Atleta e Modalidade foram selecionadas por representarem informações importantes para o funcionamento do sistema. Os atores Administrador e Responsável pelos Jogos não foram transformados em classes, pois representam os usuários que interagem com o sistema.

## 2. Classes

As classes identificadas possuem atributos que representam suas informações e operações que permitem manipular esses dados.

| Classe | Atributos | Operações |
|---|---|---|
| Atleta | idAtleta: int; nome: String; idade: int; campus: String | cadastrar(); consultar(); alterar(); excluir() |
| Modalidade | idModalidade: int; nome: String; categoria: String | cadastrar(); consultar(); listarAtletas() |

Os atributos foram definidos para identificar e armazenar as informações dos atletas e das modalidades esportivas. As operações foram definidas a partir das funcionalidades previstas nos requisitos funcionais.

### Relacionamentos

| Relacionamento | Multiplicidade | Descrição |
|---|---|---|
| Atleta – Modalidade | 0..* para 0..* | Uma modalidade pode possuir vários atletas, e um atleta pode estar relacionado a várias modalidades. |

Não foi utilizado relacionamento de composição, pois a modalidade não é uma parte inseparável do atleta. As duas classes possuem informações próprias e podem existir independentemente.

## 4. Teste de Objetos

Para verificar se o diagrama de classes representa corretamente o funcionamento do sistema, foi realizada uma simulação com objetos.

**Situação:** O atleta Pedro participa das modalidades de futebol e vôlei nos Jogos Estudantis.

### Objetos criados

**Objeto 1 – Atleta**

| Atributo | Valor |
|---|---|
| idAtleta | 1 |
| nome | Pedro |
| idade | 16 |
| campus | Ponta Grossa |

**Objeto 2 – Modalidade**

| Atributo | Valor |
|---|---|
| idModalidade | 1 |
| nome | Futebol |
| categoria | Coletiva |

**Objeto 3 – Modalidade**

| Atributo | Valor |
|---|---|
| idModalidade | 2 |
| nome | Vôlei |
| categoria | Coletiva |

O objeto Pedro está relacionado aos objetos Futebol e Vôlei. Dessa forma, o teste demonstra que um atleta pode estar associado a mais de uma modalidade, conforme a multiplicidade definida no diagrama.

## 5. Rastreabilidade com a Seção 4.2.2

A tabela de rastreabilidade relaciona as operações das classes com os casos de uso definidos na seção 4.2.2, permitindo verificar se as funcionalidades do sistema possuem operações correspondentes.

| Operação | Origem |
|---|---|
| Atleta.cadastrar() | Caso de Uso: Cadastrar Atleta |
| Atleta.consultar() | Caso de Uso: Consultar Informações do Atleta |
| Atleta.alterar() | Manutenção das informações do atleta |
| Atleta.excluir() | Caso de Uso: Excluir Atleta |
| Modalidade.cadastrar() | Cadastro das modalidades esportivas |
| Modalidade.consultar() | Consulta das informações das modalidades |
| Modalidade.listarAtletas() | Caso de Uso: Listar Atletas e Modalidades |

### Conferência da Rastreabilidade

- Todas as funcionalidades de cadastro, consulta, listagem e exclusão possuem operações correspondentes.
- As classes Atleta e Modalidade representam as principais informações armazenadas pelo sistema.
- As operações estão relacionadas às funcionalidades previstas no projeto.
- Os relacionamentos permitem representar a participação dos atletas nas modalidades esportivas.
- O diagrama de classes está alinhado ao escopo definido para o Sistema de Cadastro de Atletas.
