# 4.2.2 Modelagem de Casos de Uso

## 1. Atores

Os atores representam os usuários que interagem diretamente com o Sistema de Cadastro de Atletas.

| Ator | Descrição |
|---|---|
| Administrador | Responsável por cadastrar, editar, excluir e consultar as informações dos atletas. |
| Atleta | Responsável por visualizar seus próprios dados, realizar inscrições nas modalidades e consultar os resultados dos jogos. |
| Comissão Organizadora | Responsável por gerenciar as modalidades esportivas e definir as regras dos jogos. |

## 4. Especificação do Caso de Uso Principal

### Caso de Uso: Cadastrar Atleta

**Ator principal:** Administrador.

**Pré-condição:** O Administrador deve ter acesso ao sistema.

**Pós-condição:** O atleta é cadastrado e suas informações ficam armazenadas e disponíveis para consulta.

### Fluxo Principal

1. O Administrador seleciona a opção de cadastrar atleta.
2. O sistema apresenta o formulário de cadastro.
3. O Administrador informa os dados do atleta.
4. O sistema verifica e valida as informações fornecidas.
5. O sistema salva as informações do atleta.
6. O sistema confirma que o cadastro foi realizado com sucesso.

### Fluxo Alternativo

**A1 – Dados obrigatórios não preenchidos.**

1. No passo 4 do fluxo principal, o sistema identifica que existem campos obrigatórios não preenchidos.
2. O sistema informa quais dados precisam ser preenchidos.
3. O Administrador completa as informações.
4. O fluxo retorna ao passo 4 do fluxo principal.

### Fluxo de Exceção

**E1 – Falha ao salvar as informações.**

1. No passo 5 do fluxo principal, ocorre uma falha durante o salvamento dos dados.
2. O sistema informa que não foi possível realizar o cadastro.
3. O sistema não confirma a operação como concluída.
