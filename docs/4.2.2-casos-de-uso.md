# 4.2.2 Modelagem de Casos de Uso

## 1. Atores

Os atores representam os usuários que interagem diretamente com o Sistema de Cadastro de Atletas.

| Ator | Descrição |
|---|---|
| Administrador | Responsável por cadastrar, consultar, listar e excluir atletas no sistema. |
| Responsável pelos Jogos | Responsável por acompanhar as informações dos atletas cadastrados e suas respectivas modalidades. |

## 2. Casos de Uso

Os casos de uso representam as principais funcionalidades do sistema, conforme os requisitos funcionais definidos na seção 4.2.1.

|---|---|
| RF01 | Cadastrar Atleta |
| RF02 | Listar Atletas e Modalidades |
| RF03 | Consultar Informações do Atleta |
| RF04 | Excluir Atleta |

## 4. Especificação do Caso de Uso Principal

### Caso de Uso: Cadastrar Atleta

**Ator principal:** Administrador.

**Pré-condição:** O Administrador deve ter acesso ao sistema.

**Pós-condição:** O atleta é cadastrado e suas informações ficam disponíveis para consulta.

### Fluxo Principal

1. O Administrador informa os dados do atleta.
2. O sistema verifica se os dados obrigatórios foram preenchidos.
3. O sistema valida as informações fornecidas.
4. O sistema registra o atleta no banco de dados.
5. O sistema confirma que o cadastro foi realizado com sucesso. 

### Fluxo Alternativo

**A2 – Dados obrigatórios não preenchidos.**

1. No passo 2 do fluxo principal, o sistema identifica que existem dados obrigatórios não preenchidos.
2. O sistema informa quais dados precisam ser preenchidos.
3. O Administrador completa as informações.
4. O fluxo retorna ao passo 2 do fluxo principal.

### Fluxo de Exceção

**E1 – Falha ao registrar o atleta.**

1. No passo 4 do fluxo principal, ocorre uma falha durante o registro.
2. O sistema informa que não foi possível realizar o cadastro.
3. O sistema encerra a operação sem confirmar o registro do atleta.
