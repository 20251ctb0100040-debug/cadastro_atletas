# 4.2.1 Levantamento de Requisitos

## Como os requisitos foram levantados

O levantamento de requisitos do Sistema de Cadastro de Atletas foi realizado com base nas informações apresentadas por Carlos, responsável pela organização dos Jogos Estudantis do IFPR. A partir da descrição do problema, foram identificadas as dificuldades enfrentadas no processo manual de cadastro dos atletas, principalmente em relação à organização das informações e à consulta dos participantes.

As necessidades identificadas foram transformadas em histórias de usuário e requisitos funcionais e não funcionais. Também foram consideradas as funcionalidades definidas no escopo da seção 4.1 e representadas no diagrama de casos de uso da seção 4.2.2.

❓ A confirmar com o cliente: quais informações serão obrigatórias no cadastro dos atletas, como serão disponibilizados os resultados dos jogos e se haverá controle de acesso por login.

## Da fala à necessidade

| # | Fala | O que é | Necessidade por trás |
|---|---|---|---|
| F1 | "Preciso de um sistema para facilitar o cadastro de atletas para os Jogos Estudantis do IFPR." (Carlos) | Solução | Facilitar o registro dos atletas participantes. |
| F2 | "Atualmente o processo é manual, o que dificulta a organização das informações." (Carlos) | Necessidade | Manter os dados dos atletas organizados em um único sistema. |
| F3 | "O processo manual aumenta o risco de perder os dados dos atletas inscritos." (Carlos) | Necessidade | Manter as informações armazenadas e disponíveis para consulta. |

## Histórias de usuário

| # | História de usuário | Veio de |
|---|---|---|
| HU01 | Como administrador, quero cadastrar atletas, para manter os dados dos participantes registrados no sistema. | F1, F2 |
| HU02 | Como administrador, quero editar e excluir atletas, para manter os registros atualizados. | Escopo da 4.1 |
| HU03 | Como administrador, quero consultar os atletas cadastrados, para encontrar rapidamente as informações dos participantes. | F2, F3 |
| HU04 | Como comissão organizadora, quero gerenciar as modalidades e definir as regras dos jogos, para organizar as atividades esportivas. | Escopo da 4.1 |
| HU05 | Como atleta, quero visualizar meus próprios dados, para conferir minhas informações cadastradas. | Escopo da 4.1 |
| HU06 | Como atleta, quero me inscrever nas modalidades disponíveis, para participar das atividades esportivas. | Escopo da 4.1 |
| HU07 | Como atleta, quero consultar os resultados dos jogos, para acompanhar meu desempenho nas competições. | Escopo da 4.1 |

## Requisitos funcionais

| # | Requisito funcional | Descrição | Veio de |
|---|---|---|---|
| RF01 | Cadastrar atleta | O sistema deve permitir que o Administrador cadastre os dados de um atleta participante dos Jogos Estudantis do IFPR. | HU01 |
| RF02 | Editar atleta | O sistema deve permitir que o Administrador altere as informações de um atleta cadastrado. | HU02 |
| RF03 | Excluir atleta | O sistema deve permitir que o Administrador exclua um atleta cadastrado. | HU02 |
| RF04 | Consultar atletas | O sistema deve permitir que o Administrador consulte os atletas cadastrados. | HU03 |
| RF05 | Validar dados | O sistema deve verificar se as informações fornecidas estão preenchidas corretamente antes de realizar o registro ou a alteração. | HU01, HU02 |
| RF06 | Salvar informações | O sistema deve armazenar os dados dos atletas cadastrados e suas alterações. | HU01, HU02 |
| RF07 | Gerenciar modalidades | O sistema deve permitir que a Comissão Organizadora gerencie as modalidades esportivas dos jogos. | HU04 |
| RF08 | Definir regras dos jogos | O sistema deve permitir que a Comissão Organizadora defina as regras dos Jogos Estudantis do IFPR. | HU04 |
| RF09 | Visualizar próprios dados | O sistema deve permitir que o Atleta visualize suas próprias informações cadastradas. | HU05 |
| RF10 | Inscrever-se em modalidades | O sistema deve permitir que o Atleta realize sua inscrição nas modalidades disponíveis. | HU06 |
| RF11 | Acessar informações | O sistema deve disponibilizar ao Atleta as informações necessárias para realizar sua inscrição nas modalidades. | HU06 |
| RF12 | Consultar resultados | O sistema deve permitir que o Atleta consulte os resultados dos jogos. | HU07 |

## Requisitos não funcionais

| # | Categoria | Requisito | Veio de |
|---|---|---|---|
| RNF01 | Usabilidade | O sistema deve apresentar uma interface simples e organizada, facilitando o cadastro e a consulta das informações. | Características principais da 4.1 |
| RNF02 | Integridade | O sistema deve manter os dados cadastrados corretamente, evitando a perda de informações. | F3 |
| RNF03 | Segurança | O sistema deve restringir as funcionalidades administrativas aos usuários autorizados. | Atores e permissões da 4.1 |
| RNF04 | Organização | O sistema deve apresentar as informações dos atletas e das modalidades de maneira organizada. | Propósito da 4.1 |

## Conferência dos requisitos

Todas as histórias de usuário possuem requisitos funcionais correspondentes. A HU01 corresponde aos RF01, RF05 e RF06; a HU02 corresponde aos RF02, RF03, RF05 e RF06; a HU03 corresponde ao RF04; a HU04 corresponde aos RF07 e RF08; a HU05 corresponde ao RF09; a HU06 corresponde aos RF10 e RF11; e a HU07 corresponde ao RF12.

Os requisitos funcionais também foram relacionados aos casos de uso apresentados no diagrama da seção 4.2.2. Dessa forma, as funcionalidades descritas estão alinhadas aos atores e às interações previstas para o sistema.

As dúvidas que dependem da confirmação do cliente foram identificadas para serem esclarecidas antes da finalização do levantamento.
