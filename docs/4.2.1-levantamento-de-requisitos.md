# 4.2.1 Levantamento de Requisitos

># 4.2.1 Levantamento de Requisitos

## Como os requisitos foram levantados

O levantamento de requisitos do Sistema de Cadastro de Atletas foi realizado com base nas informações apresentadas por Carlos, cliente do projeto. A partir da descrição do problema, foram identificadas as dificuldades enfrentadas no processo manual de cadastro dos atletas que participarão dos Jogos Estudantis do IFPR, principalmente em relação à organização e à possibilidade de perda de informações.

As necessidades identificadas foram transformadas em histórias de usuário e requisitos funcionais e não funcionais, considerando os objetivos, os usuários e o escopo definidos na seção 4.1.

❓ A confirmar com o cliente: quais informações serão obrigatórias no cadastro dos atletas, se o sistema terá controle de acesso por login e se haverá alguma exigência específica de desempenho.

## Da fala à necessidade

| # | Fala | O que é | Necessidade por trás |
|---|---|---|---|
| F1 | "preciso de um sistema para facilitar o cadastro de atletas para os jogos estudantis do ifpr" (Carlos) | solução | facilitar o registro dos atletas participantes |
| F2 | "atualmente o processo é manual, o que dificulta a organização das informações." (Carlos) | necessidade | manter os dados dos atletas organizados em um unico sistema |
| F3 | "O processo manual aumenta o risco de perder os dados dos atletas inscritos" (Carlos) | necessidade | manter os dados dos atletas registrados e disponiveis para consulta  |

## Histórias de usuário

| # | História de usuário | Veio de |
|---|---|---|
| HU01 | Como administrador/responsável pelo cadastro, quero cadastrar atletas, para manter os dados dos participantes registrados no sistema. | F1, F2 |
| HU02 | Como administrador/responsável pelo cadastro, quero consultar os atletas cadastrados, para encontrar rapidamente as informações dos participantes. . | F3 |
| HU03 | Como administrador/responsável pelo cadastro, quero excluir atletas cadastrados, para remover registros de participantes que não irão mais participar dos jogos. |Escopo da 4.1|
| HU04 | Como responsável pelos jogos, quero consultar as modalidades cadastradas, para organizar a participação dos atletas nas atividades esportivas. | Escopo da 4.1 |

❓ A confirmar com o cliente: se o responsável pelos jogos também poderá consultar os dados completos dos atletas ou somente as informações necessárias para organizar as modalidades.

## Requisitos funcionais

| RF01 | Cadastrar atleta | O sistema deve permitir que o administrador/responsável pelo cadastro registre os dados de um atleta participante dos Jogos Estudantis do IFPR. | HU01 |
| RF02 | Listar atletas | O sistema deve permitir que o administrador/responsável pelo cadastro visualize a lista de atletas cadastrados. | HU02 |
| RF03 | Consultar atleta |O sistema deve permitir que o administrador/responsável pelo cadastro consulte as informações de um atleta cadastrado. | HU02 |
| RF04 | Alterar atleta |O sistema deve permitir que o administrador/responsável pelo cadastro altere as informações de um atleta cadastrado. | Quem usa e características da 4.1 |
| RF05 | Listar modalidades | O sistema deve permitir que o responsável pelos jogos visualize as modalidades cadastradas. | HU04 |
| RF06 | Excluir atleta| O sistema deve permitir que o administrador/responsável pelo cadastro exclua um atleta cadastrado. | HU03 |


## Requisitos não funcionais

| # | Categoria | Requisito | Veio de |
|---|---|---|---|
| RNF01 | Usabilidade|O sistema deve apresentar uma interface simples e organizada, facilitando o cadastro e a consulta das informações dos atletas. | Características principais da 4.1 |
| RNF02 | Integridade | O sistema deve manter os dados dos atletas armazenados corretamente, evitando a perda de informações cadastradas. | F3|
| RNF03 | 

Acesso|O sistema deve permitir que as funcionalidades de cadastro, alteração e exclusão sejam utilizadas somente pelo administrador/responsável pelo cadastro. | Quem usa da 4.1 |

## Conferência com a 4.1

| Item do escopo (4.1) | Requisitos |
|---|---|
| O sistema cadastra os atletas.| RF01 |
| O sistema lista os atletas e modalidades cadastrados. | RF02, RF05 |
| O sistema consulta as informações dos atletas. | RF03|
| O sistema exclui atletas cadastrados. | RF06 |

Toda história tem requisito. A HU01 corresponde ao RF01, a HU02 corresponde aos RF02 e RF03, a HU03 corresponde ao RF06 e a HU04 corresponde ao RF05.

Todo requisito tem origem. Os requisitos RF01, RF02, RF03, RF05 e RF06 vieram das histórias de usuário. O RF04 veio da descrição dos usuários e das características da seção 4.1, que indicam que o responsável pelo cadastro poderá alterar as informações dos atletas.

O que a conferência mostrou. Os requisitos funcionais foram relacionados às funcionalidades previstas no escopo da seção 4.1. A conferência também identificou a necessidade de manter a funcionalidade de alteração dos dados dos atletas, mencionada na seção "Quem usa" e nas características principais. As dúvidas que dependem da confirmação do cliente foram identificadas com ? para serem esclarecidas antes da finalização do levantamento.
